# 数据、评估与展示

## 1. 两类输入各自证明什么

`synthetic`产生K、真实R/t/points、带噪声观测、visible、colors、outliers。
其同列索引是已知对应，用于隔离几何和地图管理错误；**不是照片，不验证SIFT**。
GT只用于构造输入和评价，真实估计函数不能把GT参数当重建结果。
公开测试另含非单位旋转；CLI默认平行相机夹具只作起点。

真实输入为 `dataset.json` 与图像文件，目录示例：

```text
data/my_scene/
├── dataset.json
└── images/
    ├── view01.jpg
    └── ...
```

从examples复制结构，填写每张图ID、名称、camera_id、相对path，以及相机宽高和实际K。
load_dataset检查路径与实体，pipeline解码后检查图像尺寸，但它不能证明你填写的K确实标定正确。
name应与日后COLMAP image目录下的文件相对名称一致。

## 2. 真实采集与预处理

先3–8张，成功后扩为约20张：有纹理、静态、曝光稳定、相邻图重叠较高，有平移视差。
固定焦距；绕物体/场景缓慢移动而不只在原地转相机。弱纹理、玻璃反光、重复纹理、运动物体分别作为失败实验。
照片可靠标定并去畸变，JSON填去畸变后的新K。手机原图+估计焦距另列“近似内参”，不要混入主验收。

预处理会改变K：

- 缩放sx/sy：fx,cx乘sx，fy,cy乘sy；skew也按横向变换。
- 裁剪左上(x0,y0)：cx减x0、cy减y0。
- EXIF旋转/翻转：必须同步像素坐标和相机内参/轴约定，不能只更新宽高。

框架按编码像素读取，禁自动EXIF旋转；建议预先生成方向确定的去畸变图片再标定/变换K。
这里不自动缩图、不去畸变，也不猜K。必要时先用已有标定课程与OpenCV工具准备数据。

## 3. 每次运行保存什么

`outputs/run01`必须为空或不存在；下一次使用run02。保留配置、输入文件列表与哈希、
Python/NumPy/OpenCV/SciPy版本、seed、数据来源、预处理与K依据、命令、耗时。
框架自动保存config/pair统计/feature与match缓存/run_status/model/summary；
数据来源、标定细节、截图、GT评价和baseline版本填到实验报告。
若需要锁定环境，可用 `requirements-verified.txt` 重装本次验证版本，再editable安装项目。

## 4. 指标定义与合理比较

| 指标 | 定义/注意 |
|---|---|
| 注册率 | 已注册图数 / 原输入图数，不删除失败图改分母 |
| 点数/观测数 | 过滤后3D点数及其有效观测总数 |
| mean/median reprojection px | 所有存储观测上预测减实测的欧氏距离，非Sampson |
| p95像素误差 | 所有存储观测误差的95百分位，与mean/median一起看尾部 |
| 正深度比例 | 全部存储观测的正深度占比 |
| 耗时 | 明确是否包括提特征、匹配、建图、BA和输出 |

同一观测集合做BA对比；若过滤改变集合，应同时报告过滤数量与前后覆盖，低误差可能只是删掉困难点。
真实场景无GT时不能只凭低重投影误差宣称真实几何精度；结合可视化、视差、覆盖和COLMAP基线。
合成/有GT对照位置时先做Sim(3)对齐：单目世界系、旋转与尺度任意；未经对齐不能比相机绝对坐标。
旋转角误差与平移方向误差单独说明；几何指标和3DGS PSNR/SSIM不是同一个任务指标。

推荐演示目标：选定约20张可靠图，≥80%注册、≥500点、median≤2px，正深度100%。
这是此项目的起始目标；未达到要解释具体原因，不能写成通用算法性能。

## 5. COLMAP基线与导出

对照使用同一图像/K、PINHOLE、固定内参；记录COLMAP实际版本与所有非默认设置。
可以用GUI或CLI，具体选项通过本机 `colmap ... -h` 确认，不照抄不同版本命令。
核心对照：注册率、点数、误差、耗时与失败行为；不承诺达到COLMAP效果。
至少做 ratio=0.7/0.75/0.8 或BA开/关中的一项消融，其他条件固定。

导出 `sparse/0/cameras.txt,images.txt,points3D.txt`：
Camera PINHOLE为fx,fy,cx,cy；pose是Hamilton `(qw,qx,qy,qz)`、world-to-camera；
images.txt每图两行，第二行列出**原keypoints顺序**，未成点填-1；
points3D track引用 `(image_id,point2D_idx)`，与images.txt双向一致。
实体ID不要求连续，point2D_idx为零基序号。
这是无rig兼容文本模型，依据[COLMAP格式](https://colmap.github.io/format.html)。
框架只完成文本格式写入和自检；安装COLMAP后实际导入截图是你的后续验收证据。

TXT不是BIN。3DGS原始实现/数据加载版本可能要求转换或另配PLY/目录：
先检查所用仓库，再用COLMAP model_converter或其读取工具转换；有格式文件不代表已接通训练。
