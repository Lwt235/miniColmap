# M1 初始化优化：用点数上界跳过不可能胜出的候选

## 本次任务

本次只针对 `mapper.initialize_map` 的候选评估调度提供测试和开发说明，算法修改由你完成。保留现有几何估计、两视图精化、质量筛选和地图写入方式；也保留你已经完成的自适应RANSAC和八点法改动。

第一阶段保持原图对遍历顺序，只加入安全剪枝。第二阶段可尝试按匹配数降序检查；排序是可选项，不需要新增配置参数或改变现有函数签名。

当前评分是 `(最终有效点数, 有效点的中位三角化角度)`，先比较点数，再比较角度。原实现只在评分严格更好时更新，因此完全相同的评分由输入列表中更早的候选胜出。

## 为什么可以跳过

对某个图对，记：

- `M = len(pair.indices)`：已经通过上游F验证的匹配行数，不是SIFT关键点总数，也不是原始描述子匹配数。
- `C`：该候选经过精化、正深度、角度、重投影及唯一track筛选后，最终能接受的点数。
- `B`：当前最好、已通过所有候选质量门槛的初始对的最终有效点数。

现有M1每个匹配行最多贡献一个点，而且同一track只能保留一个点，因此：

\[
C \leq M.
\]

若 `M < B`，该候选的第一评分维度已经不可能追上当前最好结果，后续几何运算不会改变这一事实，可以直接跳过。

**只能用严格小于。** `M == B` 时仍可能得到相同点数、更大的三角化角度。不能用 `M <= B` 剪枝，也不能因为找到了一个可用初始对就停止。

这不是“只检查前K个图对”。若最大的若干候选全部失败，而后面的较小候选可用，仍必须继续寻找。

## 必须保持的行为

1. 剪枝必须发生在 `essential_from_fundamental` 之前，避免后续G8、三角化和 `refine_two_view`。先计算完几何再忽略结果不能通过工作量验收。
2. `B` 来自目前最好候选的 `len(accepted)`，不能用它的原始匹配数、seed点数、重投影通过行数或track过滤前的数量代替。
3. 只有通过最终点数门槛、能够成为合法候选的结果才有资格成为当前最好候选。失败候选不能用其原始匹配数抬高 `B`。
4. 后来评估的候选更差时，当前最好点数不能下降。
5. 无有效候选时仍抛出 `ValueError`，保持空地图；仍只在最终候选验证成功后写入 `model.poses` 和 `model.points`。
6. 不修改调用者的pairs列表顺序、indices、F、tracks、颜色、关键点、K或配置。
7. 不传diagnostics时仍须执行剪枝。返回值仍是 `None`；原五个位置参数和可选diagnostics接口保持兼容。

你可以继续使用原有 `best_score` / `best` 状态，也可以自行组织局部状态；测试不要求使用特定变量名或辅助函数。

注意：精化报告 `accepted=False` 不等于整个候选失败。精化器可以回退到未修改的seed；如果这个seed仍通过最终几何和track筛选，它仍是合法初始候选。控制测试特意使用这种回退，不应新增“只有精化接受才能初始化”的限制。

## 诊断约定

输入的每个候选仍应有一条诊断，最终仅一条 `selected=True`。被上界剪掉的候选没有执行几何，因此不能填入虚构的精化、seed点数或零误差。

对剪枝项补充以下字段，并自行更新 `InitialPairReport` 的类型注释：

| 字段 | 类型 | 含义 |
|---|---|---|
| `skipped_by_upper_bound` | `bool` | 被本次上界规则跳过时为true |
| `upper_bound_points` | `int` | 当前候选的M |
| `best_points_at_prune` | `int` | 跳过时的B |
| `rejection_reason` | `str` | 非空说明，明确是上界跳过 |

示意记录，不是某次运行的实测数据：

```json
{
  "images": [121, 27],
  "matches": 12,
  "selected": false,
  "skipped_by_upper_bound": true,
  "upper_bound_points": 12,
  "best_points_at_prune": 24,
  "rejection_reason": "Upper bound below best accepted point count"
}
```

reason文本可以自行措辞；其余结构化字段名按上表。未被剪枝项可以省略skip字段或填false。诊断顺序可沿用输入顺序或实际检查顺序，但不能丢项、重复或混淆图像ID。数值使用可被JSON序列化的普通Python类型，不引入NaN/Infinity。

现有Pipeline会自动把这些记录写到 `initialization.json`，工作台的初始化诊断也会显示原始JSON；本次无需增加前端参数或额外开发界面。

## 可选：更早建立一个强候选

完成原顺序剪枝后，可按M从大到小检查候选，使较强的B尽早出现，从而跳过更多工作。

需要独立考虑两种顺序：**计算检查顺序**可以改变，**评分完全相同的裁决顺序**仍须服从调用者原始pairs列表。不能依赖排序后的“第一个”来处理完全平局，也不能用图像ID替代原始位置。应在局部保留原始位置，并使用新列表安排检查，不对调用者的列表原地sort。

排序不是可用性保证。匹配最多的图对可能恢复位姿失败、缺乏视差或最终可用track太少；仍要继续寻找。
