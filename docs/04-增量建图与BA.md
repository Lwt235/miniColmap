# 增量建图与 BA

几何函数解决一对视图；系统还必须保证同一个场景点在不同图中的观测一致。
读 mapper.py 的契约，再依次实现 T1/M1/M2/M3/B1。此阶段重点是“何时写入地图、如何拒绝失败”。

## mapper 的 config 参数

三个mapper函数接收 `load_config()` 返回的**完整PipelineConfig字典**，不是仅传 `config["mapping"]`。
详细结构、字段类型/单位、各阶段门槛与覆盖示例见 [配置参数参考](08-配置参数参考.md)。

```python
config = load_config()  # 或 load_config("configs/my_scene.json")
mapping = config["mapping"]
min_angle_deg = mapping["min_angle_deg"]
max_error_px = mapping["max_reprojection_px"]
initialize_map(model, pairs, tracks, config, feature_colors)
```

M1读取geometry.min_inliers、mapping.min_angle_deg/max_reprojection_px；
M2读取顶层seed及mapping.min_pnp_points/pnp_threshold_px/max_reprojection_px；
M3读取mapping.min_angle_deg/max_reprojection_px。相机K与位姿从model读取。

## tracks、feature_colors 与 pairs 的结构

类型定义分别在 `tracks.py` 和 `mapper.py`，所有mapper入口已使用这些注解：

```python
Observation = tuple[int, int]              # (image_id, keypoint_idx)
Track = tuple[Observation, ...]            # 同一个场景点的跨图观测
tracks: list[Track]
feature_colors: dict[int, NDArray[np.uint8]]
pairs: list[VerifiedPair]                  # 仅M1初始化需要
```

一个具体的track示例：

```python
tracks = [
    ((3, 0), (11, 4), (27, 2)),  # 图3第0个、图11第4个、图27第2个关键点对应同一个场景点
    ((3, 1), (27, 7)),
]
image_id, keypoint_idx = tracks[0][1]  # (11, 4)
xy = model.images[image_id].keypoints[keypoint_idx]  # shape (2,)，像素坐标
rgb = feature_colors[image_id][keypoint_idx]        # shape (3,)，RGB
```

| 参数 | 容器与元素 | 必须遵守的约定 |
|---|---|---|
| tracks | list，每项是Track元组 | 每个track至少两幅图，每图最多一条观测；存ID和关键点索引，不存二维/三维坐标 |
| feature_colors | dict，键为image_id，值为uint8数组(N_i,3) | 每行是RGB，范围0–255；第k行必须对应同一图keypoints[k]，不同图N_i可不同 |
| pairs（仅M1） | list，每项是VerifiedPair | indices为int64(M,2)，两列分别索引image_id1/image_id2的keypoints；F为float64(3,3) |

`image_id`是model.images的字典键，不要求连续；`keypoint_idx`是对应关键点数组的**零基下标**。
`enumerate(tracks)`得到的track_id只是当前列表的位置，不是Point3D的ID；尚未三角化的track也可能存在。
RGB不是BGR或0–1浮点数。pipeline在读取图像后按关键点顺序采样并传入feature_colors，
mapper只需索引取色，不必重新读图；若重新排序/筛除关键点，必须同步重映射匹配、track与颜色行。
NumPy的NDArray注解表达dtype，不检查(N_i,3)/(M,2)等shape；shape与索引对应关系仍需按上述契约保证。

## T1：从匹配边到 track

节点是 `(image_id,keypoint_idx)`，每条几何验证后的匹配连接两个节点。
采用并查集或连通分量组织对应，重复或反向边只影响一次。
例如(10,0)↔(30,4)↔(90,2)得到一个track，三次观测应成为一个3D点。
如果同一组件还含(10,7)，它就把同一图两个不同关键点当同一物理点，存在冲突。

**第一版政策：整个冲突组件拒绝。** 这是保守教学策略，可能丢掉部分正确观测，但结果可解释且不依赖边输入顺序。
进阶可按匹配质量排序做逐边约束合并，届时更新测试与文档，不能静默改变政策。
输出每条track和track列表都稳定排序，只保留至少两图的无冲突组件。
只使用 F-RANSAC 已验证内点，不直接合并所有ratio候选。

## M1：初始化地图

1. 按内点支持量排列候选，但逐个检查几何质量。
2. 取两图K和F，调用G6/G8；用首pose(I,0)、第二pose(R,t)规定世界系与单位基线。
3. 从track中找同时包含两图的观测，调用G7，先检查足够的正深度和配置视差角支持。
4. 调用 `optimization.refine_two_view` 联合精化第二pose与点，再逐点重新检查有限、两图正深度、配置视差角、两图欧氏重投影误差。
5. 全部过滤后有效初始点数达到 `config["geometry"]["min_inliers"]`，再一次性写入初始两pose与Point3D；避免失败候选污染model。
6. RGB从传入的 `feature_colors[image_id][keypoint_idx]` 取均值/中位数并转uint8。

暂存候选结果直到成功，不要边尝试边把无效point加进正式字典。
规范检查先明确 R1=I/t1=0、||t2||=1，不能把真实合成R/t填入估计图替代恢复。
每个点observations目前只放这两幅已注册图；track中的未注册观测稍后加。
一个track只能对应一个Point3D，建立临时 `observation→point_id` 索引可从point.observations派生。

F→合法E→R/t只提供线性初值，不保证像素重投影最优。两视图精化固定第一pose和第二pose的单位平移长度，
允许第二pose的旋转与平移方向改善，支持不同K1/K2；默认预算100次函数评估。
这属于M1，不受最终 `bundle_adjustment.enabled` 开关控制，也不放宽任何质量门槛。
可选关键字参数 `diagnostics=[]` 接收各候选的精化结果和筛选数量；正式流水线保存 `initialization.json`。
实现原理、噪声对照和复现命令见 [含噪初始化修复](../reports/2026-10-16-含噪初始化修复.md)。

## M2：注册一个新相机

接口为 `register_next_image(model, tracks, config) -> bool`，不再传pairs。
注册所需的数据都能从现有输入取得：track给跨图关联，Point3D.observations将track关联到已有地图点，
model.images给新图的关键点像素，model.points给对应3D坐标。
M2据此构造2D–3D对应并调用PnP，不需要两视图F矩阵。

track不等价于原始pair数据：它是连通分量，既不保存F/匹配得分，也不区分直接匹配边与传递关联。
例如A–B和B–C形成三图track，并不证明A–C曾直接匹配。因此M1仍保留pairs，用于候选图对与相对位姿恢复。

为每幅未注册图，查其track是否已关联3D点，得到去重的(X,pixel)对应。
支持量高的图优先，低于 `min_pnp_points` 的图暂缓；不能把每条pair match都独立作为PnP观测。
已有3D点与二维关键点应各自唯一，冲突不得靠多次重复投票提高支持数。
调用 `backends.solve_pnp(X,pixels,K,threshold_px,seed)`，返回R/t及重新评分后的内点mask。

参数分别来自 `config["mapping"]["pnp_threshold_px"]` 与 `config["seed"]`。
PnP前的唯一对应数和最终保留内点数都要达到min_pnp_points；最终观测还须满足max_reprojection_px。
包装自身只保证至少6个内点，mapper仍要检查默认15点门槛；当前没有额外的内点率配置字段。

注册成功后：写Pose；只将通过深度/重投影检查的观测补到对应Point3D。
返回True且恰好增加一个相机。失败：尝试下一候选；全都失败返回False且保持原图。
下一次调用可重试暂缓图，因为前一图注册后可能新增了可用地图点。
pipeline在False时结束并记录未注册ID。你可扩展每图failure reasons报告。

PnP与三角化的已知量相反：PnP固定地图求相机，三角化固定相机求点。
PnP调用库是范围选择；你负责数据关联、候选策略、验证和地图事务。
OpenCV包装使用已去畸变像素和K，distCoeffs=None，不会帮你处理未知镜头畸变。

## M3：新增地图点

对尚未关联point的track取已注册观测；少于两幅不能成点。
选择视差角足够的一对，构造 `P=K[R|t]` 并G7得到候选X。
检查**所有已注册视图**的depth与误差，任一不合格则本版拒绝该track的新点。
这能防止初始两视图拟合很好、第三视图明显不一致的错误点进入地图。
已关联point的track不重复三角化；新增point ID必须未占用。
再次调用而无新注册观测时应新增0点，已有点/观测链接保持有效。

视差角可由世界射线 `r1=X−C1,r2=X−C2` 计算，点积归一化后clip到[-1,1]再arccos。
纯旋转的相机中心相同，不能因匹配多而强行建点。对每条track可选最大可用夹角的一对。
非线性多视图点优化留作扩展，不要把DLT结果误称已经BA。

## B1：固定长度的重投影残差

优化变量使用旋转向量r(C,3)、平移t(C,3)、点X(N,3)；K固定。
观测o指定camera_indices[o]、point_indices[o]和pixel[o]。

\[
r_o=\pi(K,R_{c(o)}X_{p(o)}+t_{c(o)})-x_o\in\mathbb R^2,
\qquad \min_\theta\sum_o\rho(\|r_o\|^2).
\]

B1输出 `[du0,dv0,du1,dv1,...]`，长度永远2O；rvec单位弧度，旋转用SciPy Rotation。
先过滤地图中的无效点，solver迭代时不能删残差行，否则参数目标与Jacobian改变。
数学投影允许负深度，但初始地图必须正深度，最终候选也必须检查。
非常接近零深度报ValueError；框架要保留原模型，不把候选错误当成功更新。

## 提供的简化 BA 如何工作

优化器读取model，不需要GT。两个初始pose作为anchors冻结，其他每图6变量、每点3变量；
观测的两残差仅依赖对应camera与point。参数索引显式映射，ID无需连续。
工程wrapper使用SciPy least_squares/trf、有限差分与稀疏依赖图，提供Huber或soft_l1。
`f_scale`是残差像素尺度。先用小场景，不将通用求解器的能力等同于COLMAP规模性能。

**固定两完整pose额外冻结了相对位姿误差。** 这比只消除单目7自由度规范更强，适合首版理解。
后续若做完整BA：固定第一pose消除6自由度，另固定一个尺度量；不要无条件冻结全部第二pose。
这里的地图BA在两图时只优化点；三图及以上可以动非anchor pose。
此前M1的两视图精化允许第二pose的5个自由度变化，两者不要混淆。
优化报告分清数值终止 `solver_success` 与接受候选 `accepted`。
同一观测集合比较实际欧氏像素误差，检查有限值/正深度；无效或恶化则保留原图。
集成脚本默认使用配置中的地图BA预算（50），可用 `--ba-max-nfev` 覆盖；
`--require-ba-convergence` 将“接受但尚未收敛”的结果作为失败，普通模式则输出警告。
