# 里程碑与开发步骤

按依赖推进，不按自然日强行赶工。一次工作采用“解释输入输出 → 写一个函数 → 跑对应测试 → 记录失败与现象”。
预计40–55小时，可用每次2–3小时的开发时段；科研阅读优先时减少时段，里程碑顺延。
所有命令在项目根执行，使用 `.\.venv\Scripts\python.exe`，下表的 `pytest` 均指 `python -m pytest`。

## P0：确认框架能使用（约1小时）

读 README 和开发文档，运行 doctor、support 测试、synthetic。
打开 `examples/dataset.example.json`，解释 camera_id/image_id/keypoint_idx。
保留两条独立记录：“工程可运行”“算法尚未实现”。

停止条件：support 全通过；能找到13个 TODO，知道每个阶段的输出是什么。
如环境失败，先记录安装错误；不要在已有 Video-LLM 环境里反复装包。

## P1：两视图几何（约12–16小时）

| 顺序 | 实现与先修 | 测试 | 必交解释/观察 |
|---|---|---|---|
| 1 | G1 投影；G2 Hartley 归一化 | `tests/core/test_geometry.py -k "g1 or g2"` | 手算像素、C与t；均距与RMS区别 |
| 2 | G3 八点法；G4 Sampson | 同文件 `-k "g3 or g4"` | 8×9零空间、rank2、阈值单位 |
| 3 | G5 RANSAC | 同文件 `-k g5` | 固定seed、外点率、refit后mask |
| 4 | G6 E；G7 DLT | 同文件 `-k "g6 or g7"` | F/E坐标与无穷远/低视差 |
| 5 | G8 四解 | 同文件 `-k g8` | 为什么符号由正深度决定？单目尺度从哪里来？ |

读 [两视图指南](03-两视图几何实现指南.md)，每项可分成1–2个时段。
先无噪声，再0.5 px高斯噪声，再20%随机外点；一次只改一个变量。
合成 GT 仅用于造观测与最终评价；算法不得输入真实R/t/points代替估计。

验收：整个 geometry 测试通过；能脱稿讲“匹配 → F → E → 四解 → 三角化”；
保存一份双视图实验（输入数/内点数/误差/失败条件）。本阶段通过尚未构成完整 SfM。

## P2：多视图 track 和增量地图（约10–14小时）

1. T1：将已经过几何验证的边组成 track；同图冲突整组件拒绝。先跑 `tests/core/test_tracks.py`。
2. M1：排序候选对，用 G6/G8/G7 检验视差、正深度和误差；选择初始对，建立唯一点-track对应。
3. M2：从已有track/point给新图生成去重2D–3D，调用提供的 PnP 包装，尝试其他候选直到成功或无进展。
4. M3：对尚未成点且含至少两幅已注册图的track三角化；检查所有已注册观测，拒绝低视差与大误差。
5. 跑 `tests/core/test_mapper.py`，先3–4图合成小场景，再5–8图；记录失败图和原因。

M1写入时初始两相机入字典顺序必须保留；M2成功只能增加一个pose，失败不能留下半个地图。
Point3D.observations是元组，新增有效观测时构造新元组；feature_colors由pipeline提供。
RGB无需自写图像读取。稳定ID分配与索引映射要自己维护，不用字典长度当已有最大ID。

验收：已知对应小场景完整注册；所有点/track一致；重复匹配不产生重复点；
缺少2D–3D证据的图可解释地不注册；运行 `validate_reconstruction` 与正深度检查。
合成“已知对应”仍不验证 SIFT 前端，真实验收另做。

## P3：简化 BA（约6–8小时）

完成 B1，运行 `tests/core/test_ba.py`。读 `optimization.py`，解释参数打包和观察顺序。
求解器、稀疏依赖关系由工程框架提供。第一版固定初始两pose、固定K，优化剩余pose及所有点。
这会冻结初始相对位姿误差，是教学简化；进阶才做固定首pose和一个尺度自由度。

复制默认配置为 `configs/ba.json`，只将 `bundle_adjustment.enabled` 改为 true；先在小场景启用。
在同一观测集合上对照启用前后误差、正深度和耗时，报告 `ba.json` 中 accepted/solver_success。
求解器停止成功不等于几何变好；恶化/无效候选必须回滚。无噪声零误差场景不要求严格下降。

验收：残差符号/索引/旋转测试通过；扰动的合法模型优化后误差不恶化，规范固定；
解释为何两相机版只动点、为何不能在solver里动态删除残差。

## P4：真实小场景与报告（约12–17小时）

按照 [数据与评估](05-数据与评估.md) 准备3–8张可靠图像，先跑默认BA=false。
看 features/matches/pairs.json，再扩大为约20图。初次失败不要直接调更多参数或加图。
在全流程通过后，用同场景/同K运行 COLMAP 基线并保存命令、版本和统计。
分别保留成功案例与低纹理/小基线等失败案例，填写 `reports/实验报告模板.md`。

针对选定20张演示图的**起始目标**：≥16张注册、≥500点、median像素误差≤2 px。
这些由数据与算法决定，不是通用质量保证。若点数少但结构正确，要解释纹理/覆盖；
不能删难图后仍沿用原分母，也不能只报告经过反复阈值过滤后的误差。

完成证据：新环境可重复命令、核心测试、真实匹配图/点云/统计、BA对照和失败分析。
基于证据重写 README 和简历，说明哪些是手写、哪些是库包装。接3DGS作为下一阶段扩展。

## 时间超预算时的收敛规则

先保住一个可靠小场景的两视图/增量闭环，再完善BA与对比。55小时仍未形成真实闭环时，
把未完成模块和原因记清楚，缩小演示数据；不要追加MVS/GUI/C++重写来掩盖问题。
