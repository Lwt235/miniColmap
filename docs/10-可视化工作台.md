# 本地重建与三维可视化工作台

界面用于操作和检查 Mini-COLMAP 的真实重建结果。三维点、颜色、相机位姿、误差与轨迹来自现有算法，
界面不补点、不修改位姿，也不把参考位姿当成估计结果。几何、track、mapper 和 BA 算法仍由原有 Python 代码执行。

## 启动

本机项目环境已经安装界面依赖。日常在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m minicolmap ui
```

默认启动 `http://127.0.0.1:8765` 并打开浏览器。所有计算与数据均在本机；前端构建资源随项目保存，
使用界面时不需要 Node，也不需要连接CDN。关闭终端中的服务时，界面会断开连接。

自定义端口或不自动打开浏览器：

```powershell
.\.venv\Scripts\python.exe -m minicolmap ui --port 8766 --no-browser
```

也可运行 `scripts/start_ui.ps1`；脚本仅调用项目虚拟环境，不改变系统执行策略。
重新安装项目或在其他机器上使用时：

```powershell
python -m pip install -e ".[ui]"
python -m minicolmap ui
```

仅需要命令行算法时，仍可使用原来的安装方式，不需要安装UI可选依赖。

## 第一次查看结果

工作台会读取项目 `data/` 下的输入清单和 `outputs/` 中已有的重建结果。
先打开 `temple_ring_8_arc_no_ba_01`：它有8台已注册相机、1283个点。
当前地图的坐标与尺度由单目重建规定，坐标单位不代表米。

- 左键拖拽旋转，右键拖拽平移，滚轮缩放；工具栏可适配全部内容、聚焦点云、重置和全屏。
- 可以显示/隐藏点云、相机与坐标轴，调节点大小和相机视锥大小。
- RGB着色显示原图采样的点颜色；误差和轨迹长度着色用于检查质量。
- 显示筛选只隐藏屏幕上的部分点，不修改模型或导出文件；同时查看显示点数与总点数。
- 选择相机或图像列表项，检查照片、内参K、世界到相机的R/t和相机中心。
- 选择三维点，检查原始坐标、颜色、观测轨迹和误差；照片上的标记区分实际关键点与重投影位置。

对照相机原图时，在照片列表或三维场景选中一台已注册相机，再点击右侧 **对齐至此相机**。
三维视图一次性移到该相机中心，并对齐它的朝向和倾斜角；随后仍可直接旋转、平移和缩放。
视野参考相机的垂直视场角，并使用三维窗口的宽高比；这是一键对齐自由视角，不是锁定的原图逐像素投影。
选点时，如果上次对齐的相机记录了此点的观测，右侧优先显示这张照片和像素标记。
点详情里的 **对齐至此观测相机** 也能完成同样操作，并保留当前点与观测。

需要重新对齐时再次点击按钮；工具栏的 **重置视角** 可回到全景。
选中其他对象或更新地图快照不会自动把自由视角拉回相机。
未注册照片没有估计位姿，因此不提供对齐按钮。以上操作均不改变重建模型。

导入独立 `model.json` 而没有原图时，点云与位姿仍可查看，照片预览会明确显示不可用。
未注册照片留在列表中，但没有估计相机视锥。

## 导入数据与设置参数

已有数据：选择项目内的 `dataset.json`，或导入带清单和图片的目录。相对目录结构必须保留。
多个清单对应不同子集时，明确选中要使用的清单。

新照片：选择图像文件或目录，填写真实共享内参fx、fy、cx、cy；界面检查图像尺寸并生成清单。
不同图像尺寸或多套内参的数据，应使用现有的多相机 `dataset.json` 格式。
当前算法输入仍要求已去畸变的针孔图像，界面不会猜内参或自动预处理图片。

参数按特征提取、几何验证、增量建图与BA分组，沿用现有PipelineConfig、默认值和单位。
可以恢复默认、加载JSON配置、校验并导出配置。启动时保存完整配置；运行中的配置保持固定，
之后在界面调整的参数用于下一次运行。

## 启动重建与查看进度

选择数据集与配置后点击开始重建。第一版同时运行一个任务，每次创建独立的输出目录。
算法在子进程运行，浏览器可继续交互；刷新页面可重新连接已有任务。

进度显示实际阶段与计数，例如8张照片提特征、28个图对匹配。初始化成功、每次相机注册和补点完成、
增量建图结束以及BA前后会产生真实地图快照；可以选择已保存快照对照。
没有新快照时保持上一份真实地图，不生成演示点，也不模拟优化中间结果。

点击取消会停止算法工作进程并保留最后有效快照和诊断。取消不等于完成；
第一版不支持从中间阶段续算，重新启动会建立新任务。关闭本地服务也会停止它管理的活动工作进程。

## 怎样判断结果

区分以下情况：

| 显示情况 | 含义 |
|---|---|
| 完成且全部注册 | 当前输入的每幅图像均成功加入地图 |
| 完成但部分注册 | 流程正常结束，仍有图像未加入地图；检查未注册列表 |
| 失败 | 数据校验、特征/匹配或建图某阶段发生错误，查看阶段与原因 |
| 取消／中断 | 任务没有完整执行，保留的快照只代表已完成的计算 |
| BA候选已接受，尚未收敛 | 模型有效且平均误差未恶化，但求解器没有满足收敛条件 |

已有TempleRing BA结果的 `accepted=true`、`solver_success=false`，界面应分别展示。
低误差只是已保留观测上的一致性；同时检查注册率、点/观测数量、P95误差、正深度和视觉结构。
匹配诊断、初始化候选以及原始日志用于进一步排查。

## 导出与开发

可下载模型JSON、PLY、COLMAP文本模型及当前运行的报告。导出的数值沿用原模型，
屏幕上的点大小、配色、旋转与筛选不会写回重建文件。

前端源代码在 `web/`，后端和已构建资源在 `src/minicolmap/ui/`。
只有修改前端源码时才需要Node：

```powershell
Set-Location web
npm ci
npm run test
npm run build
```

构建资源输出到Python包中，之后使用普通 `minicolmap ui` 启动即可。
开发模式可运行 `npm run dev`，其API请求连接本地8765端口的Python服务。

UI及接口测试环境：

```powershell
python -m pip install -e ".[dev,ui,ui-test]"
$pytestTemp = Join-Path (Get-Location).Path ('.cache/ui-tests-' + [guid]::NewGuid().ToString('N').Substring(0,8))
python -m pytest tests -q -p no:cacheprovider --basetemp $pytestTemp
```

真实浏览器流程测试需要本机Edge、已经下载的TempleRing数据，以及无BA和带BA的两份基线结果。
先保持Python界面服务运行，再在另一个终端执行：

```powershell
Set-Location web
npm ci
npm run test:e2e
```

测试使用独立的临时浏览器配置，实际操作页面并分别运行无BA、带BA重建，也验证刷新重连、取消和导入。
它会创建独立的输出与导入副本；截图和JSON报告保存在 `.cache/workbench-e2e/`。
环境变量 `WORKBENCH_URL` 可指定其他本机端口，`BROWSER_CHANNEL=chrome` 可切换到本机Chrome。
默认使用无头浏览器，需要观察测试时可运行 `node e2e/workbench.mjs --headed`。

本次验收通过202项Python测试、4项前端坐标测试，以及完整Edge浏览器流程。
细节、实测指标和截图见 [工作台验收记录](../reports/2026-10-16-workbench/README.md)。

## 代码维护入口

| 位置 | 职责 |
|---|---|
| `web/src/App.tsx` | 数据、参数、任务、历史、SSE及快照状态 |
| `web/src/Viewer.tsx`、`math.ts` | Three.js批量绘制、交互选择及显示坐标计算 |
| `web/src/Inspector.tsx` | 相机与点详情、照片观测叠加 |
| `src/minicolmap/ui/app.py` | 本地HTTP接口、静态资源和SSE |
| `src/minicolmap/ui/store.py` | 导入校验、历史、独立子进程与取消 |
| `src/minicolmap/ui/worker.py` | 调用原有流水线，落盘事件、状态和序列化快照 |
| `src/minicolmap/ui/scene.py` | 把已保存模型转换成只读场景和点详情 |

`pipeline.reconstruct(..., on_event=...)` 是可选的观察接口；不传入回调时保持原调用方式。
快照使用原模型JSON结构，先序列化再通知界面；界面不读取正在计算的可变地图。
项目 `.cache/mini-colmap-ui/` 保存任务索引，`outputs/ui_*/ui/` 保存事件与快照。
如果迁移项目目录，应保留 `outputs/` 和所需原图，再由新根目录启动服务重新发现结果。
